# دليل فتح ميزات Premium — هندسيًا وبصدق (لعرض اللجنة)

> اختبار مُصرَّح (PoC) على تطبيق اللجنة فقط. الهدف: إثبات هشاشة منطق العمل إن كان
> التحقق على العميل، وتوثيق الخطوات الهندسية بدقّة.

---

## أولًا: السؤال الجوهري — «حقيقي أم وهمي؟» (اقرأه قبل أي شيء)

فتح الميزة يكون **حقيقيًا** أو **وهميًا/تجميليًا** حسب **أين يُفرَض التحقق**:

| نوع التطبيق | ماذا يحدث عند التعديل المحلي | النتيجة |
|------------|------------------------------|---------|
| **التحقق على العميل** (`isPremium()` محلية، أو flag في SharedPreferences) | الميزة تُفتح وتعمل فعليًا | ✅ **فتح حقيقي** |
| **التحقق على الخادم** (الخادم يفحص الإيصال ويُرسل بيانات الميزة) | الواجهة قد تُظهر «Premium» لكن الميزة لا تجلب بياناتها | ⚠️ **فتح تجميلي فقط** — والخادم مُحصّن (نتيجة قوية بحد ذاتها) |

**كيف تثبت للّجنة أنه حقيقي (وليس مجرد شكل):**
1. لا تكتفِ بأن الشاشة تقول «Premium».
2. **استخدم الميزة المدفوعة فعليًا حتى النهاية** (افتح المحتوى المقفل، صدّر الملف، شغّل الوظيفة).
3. إن عملت الوظيفة كاملةً بلا خادم يرفض → **حقيقي**.
4. إن ظهرت «Premium» لكن المحتوى لم يُحمّل / الخادم رفض → **التطبيق يفرض التحقق خادميًا**، والتعديل المحلي غير كافٍ. قُل هذا بصراحة: «هذه نقطة قوة في التطبيق؛ لتجاوزها يلزم اعتراض/تزوير استجابة الخادم (Cloud MITM) لا مجرد تعديل محلي». هذا الصدق يرفع تقييمك أمام الخبراء.

## ثانيًا: المسار (أ) — تطبيق معدّل دائم (للتثبيت على جهاز رئيس اللجنة)

هذا هو سيناريو «افتح الميزات، جمّع، وقّع، ثبّت على الموبايل».

### عبر المحرك (الأسهل للعرض)
1. افتح صفحة `/reverse` (أو `/pentest`) في منصّتك.
2. ارفع APK تطبيق اللجنة → **حلّل/فكّ**.
3. من شبكة القوالب اختر **`unlockPremium`** (يعيد كل دالة `isPremium/isPro/…()Z` إلى `const/4 v0, 0x1`).
   - أضِف عند الحاجة: `removeLicense`, `bypassIntegrity` (لو فيه فحص سلامة), `bypassSSL`.
4. اضغط **إعادة البناء / تنزيل APK المعدّل** → المحرك ينفّذ: `apktool b` → `zipalign` → `apksigner` ويعيد **APK موقّعًا جاهزًا**.

### يدويًا (خطة بديلة مضمونة — أدواتك موجودة في `C:\Users\PT\Desktop\APK\`)
```bat
set APK=C:\Users\PT\Desktop\APK
set ADB=C:\Users\PT\Downloads\platform-tools\adb.exe

REM 1) فكّ التطبيق
java -jar "%APK%\apktool.jar" d committee.apk -o app_decoded

REM 2) عدّل منطق Premium في smali (المحرك يفعلها، أو يدويًا: ابحث عن الدوال ()Z واجعلها ترجع 0x1)

REM 3) أعِد البناء
java -jar "%APK%\apktool.jar" b app_decoded -o app_mod.apk

REM 4) محاذاة
"%APK%\iBotPeaches-apktool-*\zipalign" -p -f 4 app_mod.apk app_aligned.apk

REM 5) توقيع (الأسهل)
java -jar "%APK%\uber-apk-signer.jar" -a app_aligned.apk

REM => الناتج: app_aligned-aligned-signed.apk
```

### التثبيت على جهاز رئيس اللجنة (هاتف حقيقي)
> التطبيق المعدّل موقّع بمفتاح مختلف عن الأصلي، لذلك يجب **إزالة الأصلي أولًا** (توقيع مختلف = يرفض الترقية).
```bat
REM اعرف سيريال الهاتف
"%ADB%" devices
REM أزل الأصلي ثم ثبّت المعدّل
"%ADB%" -s <PHONE_SERIAL> uninstall com.committee.package
"%ADB%" -s <PHONE_SERIAL> install -r app_aligned-aligned-signed.apk
```
افتح التطبيق على الهاتف وجرّب الميزة المدفوعة **فعليًا** (اختبار «حقيقي أم وهمي» أعلاه).

## ثالثًا: المسار (ب) — فتح حيّ وقت التشغيل (بلا إعادة بناء)

للعرض الفوري أمام اللجنة على المحاكي:
```
RUN-UNLOCK.bat com.committee.package
```
- يحقن `unlock_premium.js` الذي يجبر **كل** بوابات Premium:
  - `isPremium/isPro/isSubscribed…()` → `true`
  - `isExpired/isTrial/shouldShowAds…()` → `false`
  - `getPoints/getCredits/getBalance/getRemainingDays…()` → قيمة كبيرة (999999)
  - `getPlan/getTier/getAccountType…()` → `"premium"`
- كل تعديل يُطبع: `🔓 [UNLOCK] Class.method() -> value` — دليل مباشر للّجنة.

## رابعًا: تغطية كل أنظمة الاشتراك (كما طلبت)

| النظام | آلية التجاوز | الأداة |
|--------|-------------|--------|
| **علم منطقي محلي** (`isPremium`) | إجبار `true` (patch/Frida) | `unlockPremium` / `unlock_premium.js` |
| **نقاط/توكنات/رصيد** | إجبار قيمة كبيرة | `unlock_premium.js` (FORCE_BIG) |
| **صلاحية زمنية/انتهاء** | إجبار `isExpired=false` + أيام كبيرة | `unlock_premium.js` (FORCE_FALSE/BIG) |
| **خطة/فئة (plan/tier)** | إرجاع `"premium"` | `unlock_premium.js` (FORCE_PLAN) |
| **تحقق خادمي (إيصال/API)** | التعديل المحلي تجميلي → يلزم اعتراض/تزوير استجابة الخادم | `payload_universal.js` + إعادة كتابة الرد (نقطة صدق مهمة) |

## خامسًا: الشرح الهندسي الذي تقوله للّجنة (خطوة بخطوة)

1. **الاستطلاع الثابت:** فككت الـAPK (apktool/jadx)، وكشف المحرك دوال التحقق من الاشتراك محليًا (`premiumLogic.ts` → ثغرة «التحقق يتم محليًا»، CWE-602).
2. **الاستغلال:**
   - **ثابت:** عدّلت bytecode (smali) لإرجاع `true`، ثم أعدت البناء والمحاذاة والتوقيع.
   - **ديناميكي:** ربطت الدوال بـFrida وقت التشغيل لإجبار القيم.
3. **التحقق (الصدق):** ثبّتُّ المعدّل على جهاز حقيقي واستخدمت الميزة فعليًا للتأكد أنها تعمل — لا مجرد شكل. (وإن كان التحقق خادميًا، وثّقت ذلك كنقطة تحصين.)
4. **الأثر:** بند «تجاوز منطق العمل» +30 في درجة الأثر، مع توصية: انقل التحقق للخادم مع التحقق من الإيصال ومنع إعادة الاستخدام (nonce).

> هذه المنهجية (استطلاع → استغلال بطريقتين → تحقق حقيقي → توصية) هي ما يميّز مهندسًا محترفًا عن ناسخ سكربتات.

## ملفات هذه الحزمة
- `unlock_premium.js` — الفتح الحيّ الشامل (مُختبَر: يُحقَن نظيفًا).
- `RUN-UNLOCK.bat` — تشغيل بأمر واحد.
- `payload_universal.js` + `RUN-CAPTURE-ALL.bat` — لاعتراض/تزوير استجابة الخادم (الحالة الخادمية).
- قوالب `unlockPremium`/`rebuildAPK` — داخل المحرك (`services/reverse-engineer.ts`).
